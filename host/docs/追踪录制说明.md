# OSMO 上位机追踪录制说明

本文档对应当前 `THost` 中的两个上位机：

- `姿态测试上位机.pyw`
- `纯数据预览.pyw`

默认行为：

- 姿态上位机启动后会在 `THost\recordings` 自动新建一个 trace session。
- 纯数据预览从开始菜单/脚本直接启动时也会自动录音；被测试脚本 `import` 时不会自动录音。
- 点击窗口中的“停止追踪录制”可正常收尾并关闭 manifest。
- 停止后可再次点击“开始追踪录制”，选择任意父目录新建 session。
- 姿态上位机可用 `--no-auto-trace` 禁用启动自动录制。

## 每次录制的内容

每个 session 是一个独立目录：

```text
THost/recordings/YYYYMMDD_HHMMSS_pose_monitor_trace/
├─ manifest.json
├─ serial_stream.bin
├─ serial_chunks.jsonl
├─ firmware_diagnostics.jsonl
├─ gate_events.jsonl
├─ raw_frames.bin
├─ frames.jsonl
├─ stages.jsonl
├─ analysis.csv
├─ events.jsonl
└─ system.jsonl
```

### `raw_frames.bin`

最原始的 COBS 帧二进制证据，不经过 protobuf 解码。格式：

```text
OSMOTRC1
[8 字节 trace_id][8 字节 rx_monotonic_ns][4 字节 payload_len][payload]
...
```

`payload` 是 USB CDC 原始 COBS 编码内容，不包含末尾 `0x00` 分隔符。测试程序可以按 `trace_id` 回放、注入或与 `frames.jsonl` 逐条校验。

### `serial_stream.bin` / `serial_chunks.jsonl`

`serial_stream.bin` 保存串口线程实际从 USB CDC 读到的连续原始字节流，包含分隔符、文本诊断、错误帧和未成帧残留，按读入顺序原样追加。`serial_chunks.jsonl` 为每个写入批次记录：

- `connection_id`
- 写入前在 stream 中的字节偏移 `offset`
- 批长度 `length`
- 首/末接收 monotonic 时间
- SHA-256 和十六进制内容

因此不仅 COBS 帧本身可回放，串口层看到的完整数据流也可重建。
### `frames.jsonl`

每条原始帧对应一条 JSON：

- `trace_id`、连接编号、串口接收序号
- 接收 wall clock / monotonic clock
- 原始 payload 长度、SHA-256、十六进制
- COBS/protobuf 解码结果或具体失败原因
- 完整 Bowie protobuf 字段

即使 COBS 或 protobuf 解码失败，原始帧仍会录入，不会被静默丢弃。

### 帧级 protobuf 原始证据

`frames.jsonl` 除 COBS 原始帧外，现在还记录：

- `packet_hex`：COBS 编码帧
- `protobuf_len`
- `protobuf_sha256`
- `protobuf_hex`：COBS 解码后的 protobuf payload

这样可以在 protobuf 解析器升级、字段默认值变化或 betterproto 版本变化时重新解析历史原始数据。

### 运行与文件完整性

- `system.jsonl` 每秒记录进程 CPU 时间、线程数量、线程名、工作集/峰值内存、pagefile、磁盘剩余空间和 trace 队列状态。
- `system.jsonl` 同时记录最终 render 状态：当前/相对 quaternion、yaw、轴模式、传感器筛选、canvas 尺寸和 cube screen points。
- session 正常关闭后，`manifest.json` 写入 `host_files`、依赖版本和 `artifacts` 逐文件 SHA-256/字节数清单。
- 断开时若还有未成帧残留，记录 `unterminated_buffer` 事件，同时原始字节仍保留在 `serial_stream.bin`。
### `stages.jsonl`

记录上位机处理链的当前值，而不是只记录最终 UI 字符串。

姿态链路包括：

- 原始四元数 `w/x/y/z`、模长
- 归一化四元数
- 校准参考四元数
- 相对姿态四元数
- 原始 yaw、相对 yaw
- 相邻帧角度差、时间差、角速度中位数
- `accuracy` 拆包后的状态码、标定结果、诊断位、权重和故障位
- 传感器筛选、坏数据、重复 `index` 等分支

磁链路包括：

- 原始磁矢量、单位换算后的磁矢量
- 世界坐标系磁矢量
- 主/副磁传感器、共模矢量、差分矢量
- 差分基线、动态差分
- 原始模长、低通模长、上一帧低通值、dt、EMA alpha
- 磁状态机 `state_before`、`state_after`、判定原因
- 参考矢量、夹角、模长相对变化
- 指南针状态、质量、噪声、跳变、yaw 误差

### `firmware_diagnostics.jsonl` / FIX14/FIX20 诊断

FIX14/FIX20 与 COBS/protobuf 共用 CDC 端点，并输出额外文本诊断。主机现在逐条保存完整原文，同时实时解析以下类型：

- `GQ`：原始 GAMERV 四元数整数、`accuracy`、`yawc`。
- `GY`：passthrough gyro、corrected gyro、`CV` 有效性、内部 bias、activity、`motion_hold`。
- `MAG`：RAW、CAL、OFF、模型 revision、fixes、learning opens/state、datum、yawc。
- `SINFO`：sensor id、driver、range、resolution、max/min rate；仅固件启动时输出。
- `P` 状态表：status、trust、半径、模型、残差、align、grad/thr、drift、dip、stuck、fixes、所有门控/误差项、权重、候选、datum/yawc、revision、learning state/opens。
- `[MAG]`：load/store/restore/recalibration/learning 事件。
- 其他启动或诊断文本：保留原始行并分类为 `text`。

姿态上位机默认每 5 秒自动发送一次 `P` 来积累完整磁状态表，可以通过窗口里的“P状态5秒”取消。每个 `P` 命令及发送结果同时记录到 `events.jsonl`。`GQ/GY` 是 FIX14 诊断构建的连续 1 Hz 诊断流，会自动实时积累；FIX20 生产快照通常关闭这些文本。

所有解析记录同时注入：

- `firmware_diagnostics.jsonl`：逐条原文 + 结构化字段
- `system.jsonl`：1 Hz 快照携带最新固件诊断
- 姿态窗口：实时显示最新固件诊断状态
- 纯数据预览：显示原文和简化状态
### `gate_events.jsonl` / 运行中实时门控

FIX14/FIX20 每个四元数帧携带 `accuracy` 诊断位。主机对每一帧解析：

```text
0x01 calibration_missing
0x02 reference_dip_missing
0x04 norm_gate
0x08 dip_gate
0x10 step_gate
0x20 gradient_gate
0x40 drift_or_diag_hold_gate
0x80 hard_event_or_candidate_gate
```

每当某一位从 0→1 或 1→0，写入独立 gate event：

```json
{
  "source": "accuracy",
  "phase": "enter",
  "gate": "gradient_gate",
  "old_value": 0,
  "new_value": 1,
  "duration_ms": null,
  "trace_id": 123,
  "rx_monotonic_ns": 123456789,
  "context": {
    "diagnostic_mask": 32,
    "status": "DEGRADED",
    "cal_result": 1,
    "weight": 0.72
  }
}
```

同时记录：

- `mag_status` 状态变化
- `mag_cal_result` 标定结果变化
- `GY` 的 corrected stream validity、motion hold active 变化
- `MAG` 的 learning state、revision、fixes、learning opens 变化
- `P` 表的 rejecting、hard event、candidate valid、dip valid、model、align、learning state 变化

`duration_ms` 给出门控保持时间。第一次看到某个门控已激活时写入 `initial_active`，避免漏掉启动瞬间已经存在的门控。
### `analysis.csv`

便于 Excel、pandas、MATLAB 快速分析的扁平表。每一行由 `trace_id` 与原始帧和 stage 记录关联。JSONL 是完整记录，CSV 用固定列裁剪为常用测试字段。

### `events.jsonl`

记录用户/系统行为：

- 串口连接、断开、重连失败
- H/J/K/G/R 串口命令及发送结果
- 空格校准、磁差分归零、界面配置切换
- 窗口关闭、录制启动/停止
- decode error、duplicate index、坏 quaternion、坏 mag

### `system.jsonl`

1 Hz 快照，包括：

- 串口连接状态、端口
- quat/mag 每秒帧率
- 事件队列深度
- 最后一帧 trace_id、处理延迟
- 当前四元数、参考四元数、角速度
- 磁状态机和差分基线
- 录制器写入计数、队列深度、丢弃计数

### `manifest.json`

session 元数据、脚本 SHA-256、Python/平台、端口和 UI 配置、开始/结束时间、总统计和录制器丢包提示。

## 离线重新录入与算法测试

原始 trace 不需要再连接手套，可以直接重新解码并喂回当前上位机算法：

```powershell
cd THost
python trace_replay.py decode "recordings\YYYYMMDD_HHMMSS_pose_monitor_trace" --limit 20
python trace_replay.py replay-pose "recordings\YYYYMMDD_HHMMSS_pose_monitor_trace" --output "recordings" --speed 0
python trace_replay.py replay-pose "recordings\YYYYMMDD_HHMMSS_pose_monitor_trace" --output "recordings" --speed 1 --sensor 13
```

`decode` 从 `raw_frames.bin` 重新执行 COBS/protobuf 解码。
`replay-pose` 会：

- 重新解码每一个原始帧
- 复用原 trace 的 `rx_monotonic_ns` 作为算法 dt 时间轴
- 调用与实时上位机相同的四元数和磁处理函数
- 新建一个 replay trace session，保留 `source_trace_id -> 新 trace_id` 映射
- 写入相同的 `analysis.csv`、`stages.jsonl`、`system.jsonl` 和 manifest

`--speed 0` 尽可能快、但不改变算法时间轴，适合回归和参数对比；`--speed 1` 按原始时间间隔实时回放。

作为模块使用时：

```python
from trace_replay import iter_raw_frames, iter_decoded_rows, replay_pose

for frame in iter_raw_frames(source_session):
    raw_cobs = frame.payload
    source_time_ns = frame.rx_monotonic_ns
```

这样新的离线算法可以直接接管 `raw_cobs` 或解码后的 `row`，并把输出与原始 trace 逐 `trace_id` 对齐。
## 校验与汇总

在 `THost` 目录执行：

```powershell
python trace_session.py summary "recordings\YYYYMMDD_HHMMSS_pose_monitor_trace"
python trace_session.py verify "recordings\YYYYMMDD_HHMMSS_pose_monitor_trace"
python trace_session.py export-csv "recordings\YYYYMMDD_HHMMSS_pose_monitor_trace"
```

`verify` 会逐条检查：

- `raw_frames.bin` 记录是否完整
- `frames.jsonl` 与二进制帧数量和 `trace_id` 是否一致
- 帧长度、monotonic 时间、SHA-256 是否一致

## 已生成的真实样例

本次改造已用 COM3 手套数据生成并验证一对真实 session：

```text
原始采集：
THost\diagnostics\real_smoke_traces\20260921_155154_pose_monitor_trace

离线重放：
THost\diagnostics\real_smoke_traces\20260921_155202_pose_replay_trace
```

验证结果：

- 原始帧 414
- 成功解码 410
- 解码错误 4，坏帧仍保留
- 录制器丢弃 0
- `serial_stream.bin` SHA-256 前后一致
- `raw_frames.bin` SHA-256 前后一致
- replay 中重新生成了 410 条算法 analysis/stage 记录

可直接用该样例验证新的离线算法：

```powershell
cd THost
python trace_replay.py replay-pose "diagnostics\real_smoke_traces\20260921_155154_pose_monitor_trace" --output "diagnostics\my_algorithm_runs" --speed 0
```
## 测试注意事项

- trace 写入使用独立后台线程，串口线程不等待磁盘写入。
- 队列上限为 50000 条。若磁盘或系统过慢，`manifest.json` 和界面会明确显示 `dropped`，不会伪装成完整数据。
- `raw_frames.bin` 是主要复现依据；`frames.jsonl` 是方便人工检查的数据视图。
- `analysis.csv` 中空值表示当前帧类型没有该字段，不等于数值 0。
