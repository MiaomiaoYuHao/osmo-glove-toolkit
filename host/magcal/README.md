# 上位机磁标定工具 (magcal)

**转一次，算法在本地反复调，不用再动板子。**

## 为什么这样拆

固件自己能做椭球拟合，但它只能做**一次普通最小二乘**，而且原始样本不留。
本工具把"采集 → 拟合 → 上传"拆开，于是同一份采集数据可以：

- 反复换算法重拟合
- 先看残差和覆盖再决定要不要写进板子
- 完全不用重新翻滚

## 相对固件拟合的四点增强

| # | 增强 | 解决什么 |
|---|---|---|
| 1 | **IRLS / Huber 鲁棒加权** | 抗离群点。转的过程中手靠近口袋、门开一下、磁铁路过，固件会把这些脏样本一起拟合进去；这里自动降权 |
| 2 | **SVD (lstsq) 而非正规方程** | 不平方条件数。几千样本、磁值几千 LSB 时，正规方程会掉 float32 精度 |
| 3 | **姿态一致性剔除** | 用相邻四元数预测磁场该怎么转，预测不了的样本判为干扰 |
| 4 | **覆盖密度反加权** | 24 个球面区块按密度反加权，扎堆方向不再被过度加权 |

## 用法

**推荐路线：上位机一直开着，用它新增的【标定采集】按钮。**

> ⚠️ 【标定采集】和【追踪录制】是**两件事**，别用错：
>
> | 按钮 | 写什么 | 用途 |
> |---|---|---|
> | **开始标定采集** | **一个 CSV**（`kind,time,x,y,z,w`） | **磁标定** ← 用这个 |
> | 开始追踪录制 | 10 个文件（raw_frames / frames / stages / events / system / analysis / serial_stream / serial_chunks / firmware_diagnostics / gate_events） | 调试追踪 |
>
> 追踪录制对标定来说有 90% 是无用数据，而且那堆磁盘 I/O **本身就可能造成丢帧**。
> 标定采集只写一个文件，一行一个包，开销最小。

```
1. 上位机连上，按【开始磁标定 (H)】
2. 点【开始标定采集】→ 选保存位置
3. 翻滚（看着上位机的磁诊断窗口）
4. 点【停止标定采集】
```

然后转换 + 拟合 + 上传：

```bat
cd host\magcal

:: 把采集转成可拟合的数据
python magcal.py fromtrace "D:\cal_20260921_xxxxxx.csv" --out sweep1.npz

:: 本地拟合（随便跑多少次）
python magcal.py fit sweep1.npz

:: 结果满意就推回板子（会写进固件 Flash）
python magcal.py upload sweep1.npz.blob
```

`fromtrace` 读的是上位机录的 `analysis.csv`，里面本来就有
`mag_x_raw / quat_*_norm / *_device_time_s` —— 所以**不用去抢串口**。

---

**备用路线**（不打开上位机，直接抓串口，不限时按 Enter 停）：

```bat
python magcal.py collect --out sweep1.npz
```

两条路产出的 npz 格式一样，后面 `fit` / `upload` 完全通用。

### 采集是【不限时】的

**由你看着实时面板决定什么时候停**，不是定时：

```
  t=  62.3s  磁= 6231  姿态=24910  100.0Hz  丢0    覆盖=19/24  跨度= 98/142/105%
```

| 字段 | 什么时候算够 |
|---|---|
| `覆盖` | **≥ 18/24**（面板是未标定方向的粗估，最终值看 fit 报告）|
| `跨度` | **三个都要 ≥ 100%** |
| `丢` | **必须是 0**。不是 0 就先别继续，告诉我 |
| `磁=` | 越多越好，但覆盖率才是关键 —— 覆盖满了再多意义不大 |

看到三个指标都到位，**按 Enter 停止**。
（`--duration 180` 仍然可用，但一般不要用。）

### 采集前

1. 按上位机的 **`开始磁标定 (H)`** —— 这会清空当前标定，
   于是固件上传的磁矢量就是**原始值**（只过了 FIR），正是拟合需要的
2. **关闭上位机**（Windows 串口独占，不能同时开）
3. 挪到干净的地方（远离电脑/手机/音箱/磁铁/金属桌）

### 采集动作

三组，之间不要停：

- **水平转圈** 2~3 圈（每圈约 8 秒）
- **竖起来转圈**：一条边朝上转 2~3 圈，换另一条边再 2~3 圈
- **三维翻滚**：同时改俯仰和横滚，让 6 个面轮流朝上朝下，连续 1 分钟以上

慢、连续、每个方向都要到，特别是**把板子彻底翻过来**。

### 达标线

| 指标 | 门槛 |
|---|---|
| 球面覆盖 `bins` | **≥ 16 / 24** |
| 三轴 span | **都 ≥ 100%** |
| 残差 p95 | **< 0.02**（2% 场半径）|
| `det(W)` | **= 1** |

## 参数约定（必须和固件严格一致）

```c
u      = W * (raw - offset) / radius        |u| ~ 1
m_out  = A * u * radius                     A = 磁->IMU 旋转
```

- `offset / W / radius` 描述椭球**形状**
- **`W` 必须是 `Mn = W^T W / radius^2` 的对称平方根**，`det(W) = 1`

  ⚠️ 这条是关键。椭球只能确定 `W^T W`，`W` 本身可以差一个旋转。
  固件的 `mf_m3_sqrt()` 用的是 Denman-Beavers 迭代 → **对称**平方根。
  如果这里用 Cholesky，`W` 就和固件的约定差一个旋转，而上传时固件会
  **保留它自己的 `A`**，两者不匹配会让航向整体偏一个固定角度。

- `A`（磁→IMU 旋转）、`dip`、`map` 是**板子自身属性**。上传时固件会
  **保留自己的**（见 `glove.c` 的 `glove_mag_upload`），上位机给的这几个
  字段会被忽略，所以可以填单位阵。

## 上传协议

命令字节 `'C'`（0x43）之后紧跟一个小端帧：

```
u32 magic  = 0x4D414743 ("CGAM")
u32 nbytes = 200  (sizeof(mag_cal_blob_t))
u8  blob[nbytes]
u32 fnv1a32(blob)
```

板子收到后：校验 → `mag_fusion_load()` 装进 RAM → 直接写进 Flash 第 7 扇区。
回应会打印 `[UP] calibration accepted on N link(s)`。

## 文件

| 文件 | 作用 |
|---|---|
| `magcal.py` | 三合一：collect / fit / upload |
| `test_fit.py` | 合成数据自检（验证约定对齐 + 抗离群） |
| `mkdemo.py` | 造一份合成 npz，用于离线跑通流程 |
| `mergeall.py` | 合并多次 `cal_*.csv` 采集，生成 `allsweep.npz` |
| `lab/` | 历史实验脚本，需按本地数据路径或串口调整 |

## 自检

```bat
python test_fit.py
python mkdemo.py && python magcal.py fit demo_sweep.npz
python mergeall.py "..\..\recordings"
```

`test_fit.py` 会检查还原出的 `W` 是否**对称且 det=1**，以及 offset/radius 的
还原误差 —— 这是验证"约定对齐"的唯一手段，改完算法务必跑一遍。

## 实验脚本

`lab/` 保存了开发期间用过的一次性分析/诊断脚本。它们不属于主流程，部分脚本仍含历史录制目录、COM3 或固件路径，使用前需要按实际情况修改。公开仓库的主流程只依赖根目录下的 `magcal.py`、`magcal_view.pyw` 和自检脚本。
